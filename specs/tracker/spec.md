# Спецификация мини-трекера

## ADDED Requirements

### Requirement: Автономный интерфейс

Трекер MUST работать при открытии `tracker-v2.html` с локального диска. CSS и JavaScript MUST быть встроены в файл. Трекер MUST обходиться без CDN, сторонних библиотек и внешних API. Поля и кнопки MUST иметь подписи.

#### Scenario: Интерфейс при ширине 390 px

- **WHEN** пользователь открывает файл при ширине области просмотра 390 px
- **THEN** горизонтальная прокрутка отсутствует, поля и кнопки подписаны.

### Requirement: Задачи и начальное состояние

Каждая задача MUST содержать `id`, `title`, `hours` и `done`. Добавление MUST создавать задачу со статусом «активна». Удаление MUST убирать выбранную задачу, а переключение статуса MUST менять её `done` на противоположное значение.

#### Scenario: T1 — первый запуск

- **WHEN** трекер запускается впервые
- **THEN** в списке видны «Чтение» (2 ч, готово), «Практика» (4 ч, активна) и «Повторение» (2 ч, активно), а прогресс показывает 2 из 8 ч и 25%.

### Requirement: Проверка формы

Название MUST сохраняться после удаления пробелов по краям и MUST быть непустым. Часы MUST быть числом от 0,5 до 24 включительно с шагом 0,5. При недопустимом вводе трекер MUST показать ошибку рядом с каждым ошибочным полем, сохранить оба введённых значения и оставить список задач прежним.

#### Scenario: T4 — недопустимый ввод

- **WHEN** пользователь отправляет форму с пустым названием или названием из одних пробелов, либо с пустыми, отрицательными, нечисловыми часами, часами вне диапазона или вне шага
- **THEN** задача не добавляется, ошибки отображаются у соответствующих полей, введённые значения сохраняются.

#### Scenario: T4 — границы диапазона

- **WHEN** пользователь добавляет задачу с непустым после обрезки названием и значением 0,5, 24 или промежуточным значением с шагом 0,5
- **THEN** трекер добавляет активную задачу с обрезанным названием и указанными часами.

### Requirement: Общий прогресс и фильтры

Трекер MUST показывать часы готовых задач, часы всех задач и процент, округлённый до целого. Процент MUST вычисляться как 100 × часы готовых / часы всех. При пустом списке трекер MUST показывать 0 из 0 ч и 0% без `NaN` или `Infinity`. Фильтры «Все», «Активные» и «Готовые» MUST менять только отображаемый список.

#### Scenario: T2 — переключение Практики

- **WHEN** пользователь отмечает «Практику» готовой из начального состояния
- **THEN** прогресс показывает 6 из 8 ч и 75%.

#### Scenario: T3 — фильтр активных

- **WHEN** пользователь выбирает «Активные» из начального состояния
- **THEN** отображаются «Практика» и «Повторение», а прогресс остаётся 2 из 8 ч и 25%.

#### Scenario: Фильтры «Готовые» и «Все»

- **WHEN** пользователь выбирает «Готовые» из начального состояния, затем «Все»
- **THEN** сначала видна только задача «Чтение», затем видны все три задачи. Прогресс в обоих случаях составляет 25%.

#### Scenario: T5 — удаление всех задач

- **WHEN** пользователь удаляет все задачи
- **THEN** список пуст, а прогресс показывает 0 из 0 ч и 0%.

### Requirement: Поведение при недоступности опционального хранилища

Если реализовано хранение в `localStorage`, трекер MUST продолжать работу с данными в памяти при недоступности хранилища и MUST сообщать об этом пользователю.

#### Scenario: Недоступное хранилище

- **WHEN** трекер с опциональным сохранением не может прочитать или записать `localStorage`
- **THEN** пользователь видит сообщение о работе в памяти и может продолжать добавлять, удалять и переключать задачи.
